# PollingSystem.Data

Репозитории находятся в `Repositories/` и получают существующий `AppDbContext` через конструктор. Интерфейсы и реализации используют `CancellationToken`.

- `IUserRepository`: `AddAsync`, `GetByEmailAsync`, `GetByIdAsync`.
- `ISurveyRepository`: `AddAsync`, `GetByIdAsync`.

Для добавления пользователя вызывающая сторона передаёт готовые `Login`, `Email`, `NormalizedEmail` и `PasswordHash`. Нормализация email: `Trim().ToUpperInvariant()`. Репозиторий применяет её к поисковому аргументу, но не изменяет переданного пользователя. Ошибки записи и уникальности передаются вызывающему коду.

Для создания опросника передайте `AuthorId` существующего пользователя и заполните `Questions` и вложенные `Options`. Навигацию `Author` оставьте незаполненной: репозиторий отклоняет заполненную навигацию, чтобы EF не попытался вставить пользователя вместе с опросником. Для Text-вопроса допустима пустая коллекция вариантов. Граф сохраняется одним `SaveChangesAsync` со стандартной транзакционностью EF Core. Этот вызов также сохраняет остальные ожидающие изменения того же контекста.

Чтение использует `AsNoTracking`. Получение опросника включает только вопросы и их варианты, отсортированные по `Position`; прохождения и ответы не загружаются. При отсутствии записи возвращается `null`.

## Login и миграции

`users.login` — обязательный `varchar(50)` с уникальным индексом `ux_users_login`. Нормализация логина не выполняется; обычная уникальность PostgreSQL чувствительна к регистру.

Миграция `AddUserLogin` добавлена после `InitialCreate`, существующая миграция сохранена. Она рассчитана на пустую таблицу `users`. Если пользователи уже существуют, проверка в начале миграции остановит применение без изменения их данных. Для такой базы сначала нужен отдельный согласованный переход: добавить nullable-колонку, заполнить уникальные логины существующих пользователей, проверить длину и дубликаты и только затем установить NOT NULL и UNIQUE. Автоматические логины и общее значение по умолчанию не назначаются.

Команды из корня репозитория:

```bash
dotnet restore PollingSystem.sln
dotnet build PollingSystem.sln
dotnet ef migrations has-pending-model-changes --project backend/PollingSystem.Data
```

EF CLI версии 8.0.31 использует `AppDbContextFactory`; строка подключения задаётся переменной `DATABASE_URL`. Создание миграций и сравнение модели не требуют подключения к PostgreSQL. Применение миграций выполняется отдельно и требует проверки состояния целевой БД.
